# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Rails 8.1 + [Inertia Rails](https://inertia-rails.dev) + React 19 (TypeScript), built with Vite. Tailwind CSS + shadcn/ui ("new-york" style, neutral base, see `components.json`). PostgreSQL, Solid Queue/Cache/Cable, RSpec, Kamal deploy. Based on the [Inertia Rails React Starter Kit](https://github.com/inertia-rails/react-starter-kit).

## Commands

```bash
bin/setup --skip-server   # install deps, create & migrate db
bin/dev                   # run Rails (:3000) + Vite dev server

bin/ci                    # run the FULL local pipeline — matches CI; run before considering work done
bin/rubocop                              # Ruby lint (Omakase style)
bin/rspec                                # all specs
bin/rspec spec/requests/sessions_spec.rb          # one file
bin/rspec spec/requests/sessions_spec.rb:12       # one example by line
bin/brakeman --no-pager                  # Ruby security static analysis
bin/bundler-audit                        # gem vulnerability audit

npm run lint          # ESLint
npm run lint:fix
npm run format        # Prettier check
npm run format:fix
npm run check         # tsc (app + node configs)
bin/rails typelizer:generate:refresh     # regenerate app/javascript/routes/* from Rails routes
```

`bin/ci` (defined in `config/ci.rb`) is the authoritative check: setup, rubocop, JS lint/format/typecheck, a freshness check on generated routes, gem/npm/Brakeman audits, then RSpec and a seed-replant check. CI (`.github/workflows/ci.yml`) runs the equivalent steps split across jobs.

## Architecture

**Auth is hand-rolled, not Devise.** `User` uses `has_secure_password` plus `generates_token_for` (Rails 7+ built-in) for email verification and password reset tokens — no `authentication-zero`/Devise models beyond that gem being present in the Gemfile just to track its security advisories. Signed-in state is a `Session` row (`app/models/session.rb`) referenced by a signed, permanent `session_token` cookie; there is no server-side session store beyond that table. `Current` (`app/models/current.rb`, an `ActiveSupport::CurrentAttributes`) holds the request-scoped `session`/`user`/`user_agent`/`ip_address` and is populated in `ApplicationController#set_current_request_details` / `#perform_authentication`. Changing a user's password deletes all of their other sessions (`User#after_update` callback); changing their email flips `verified` back to false.

**Two-tier controller base:** `ApplicationController` handles auth/CurrentAttributes for every request. `InertiaController < ApplicationController` is the `inertia_rails` `parent_controller` and is what Inertia-rendering controllers should inherit from — it globally shares the `auth: { user, session }` prop via `inertia_share`. Controllers that skip auth (sign-in, sign-up) use `skip_before_action :authenticate` + `require_no_authentication` rather than a separate base class.

**Routing is type-safe end-to-end.** `app/javascript/routes/**` is generated by the `typelizer` gem from `config/routes.rb` — **never hand-edit it** (files are marked "DO NOT MODIFY" and regenerated via `bin/rails typelizer:generate:refresh`). Use the generated helpers (e.g. `dashboard()`, `signIn()`, `settingsProfile()`) from `@/routes` instead of hardcoding URL strings in React. `bin/ci` fails if the generated routes are stale relative to `config/routes.rb`.

**Inertia page/layout structure:** controllers render with `render inertia: "page/name"`; the matching component lives at `app/javascript/pages/page/name.tsx`. Every page is wrapped in `PersistentLayout` (`app/javascript/layouts/persistent-layout.tsx`, set as the global Inertia `layout` in `entrypoints/inertia.tsx`) which mounts the flash-to-toast bridge (`useFlash`, reading the `flash` Inertia prop, rendered via `sonner`) and the `Toaster`. Pages additionally compose `app-layout`/`auth-layout`/`settings/layout` as needed. shadcn/ui primitives live under `app/javascript/components/ui/` and are excluded from ESLint/ignored as generated/vendored.

**SSR is enabled by default** (`config.ssr_enabled = true` in `config/initializers/inertia_rails.rb`, `ARG SSR_ENABLED=true` in `Dockerfile`) — the Vite SSR bundle (`vite.config.ts` `ssr` entry, `entrypoints/inertia.tsx`) is built and shipped. To disable, flip both the initializer and the Docker build arg.
